# SEO/GEO P0–P1 Implementation Plan

> **For agentic workers:** Use executing-plans. Execution is inline and staged; the user requests local changes only.

**Goal:** Deliver correct public HTML and indexing signals without changing CRM behavior, design or authentication.

**Architecture:** Generate six commercial documents at build time with existing Vite/React components. Keep operational routes client-rendered using a separate non-indexable shell. Reuse the same route metadata in generated HTML and client navigation.

**Tech Stack:** Existing React 19, React Router, Vite, Workbox, Laravel, Vitest and Playwright. No new dependencies.

## Scope and baseline

The explicit user request and `docs/SEO_GEO_AUDIT.md` define acceptance. GitHub issue search returned no SEO issue; no issue/PR is created. Current branch and existing uncommitted work are retained as requested. A SHA-256 baseline of source files is stored outside the repository in the temporary directory. No commits or publication.

1. P0 metadata and privacy: add regression tests for allowlisted canonicals, query handling, operational exclusions and backend error/success headers. Run them red, implement shared metadata and response headers, rerun focused tests.
2. P0 content: align existing commercial copy and its tests with external deliveries, local AI history, free access and optional support. Preserve classes/animations and existing safe support links.
3. P1 generation: test commercial server rendering and shell separation. Add a Vite build plugin that renders existing public route components before Workbox generates precache revisions. Hydrate only marked commercial documents; preserve SPA behavior elsewhere.
4. Routing: generate TXT/XML from the allowlist; configure Vercel/Nginx to serve public files, operational shell, redirects and true 404s. Exercise the built artifact through Vite preview and verify the committed hosting rules in regression tests.
5. Verification: run frontend/backend tests, lint, format, build, E2E/PWA and production-artifact SEO tests. Measure public pages with installed Lighthouse. Record all 15 audit criteria with PASS/PARTIAL/BLOCKED and actual evidence.
6. Documentation: update audit, architecture, deployment, testing and roadmap; retain historical production observations separately from local implementation results.

## Boundaries

- Production token/slug 500s are rechecked read-only. Only fix a demonstrated code cause; otherwise retain the incident and document the missing diagnostic evidence.
- No style, animation, ownership, auth or API payload changes. Audit requirements concerning contrast/menu restyling remain outside this request.
- Search Console, remote hosting behavior, production SHA and field metrics cannot pass from local tests; final production verification awaits authorized publication.
- Native Vite/React SSG is preferred to browser snapshots. No runtime SSR, framework migration, crawler-specific content or personalized HTML.

## Execution result

All six implementation/verification stages ran locally. Final evidence is recorded in `docs/SEO_GEO_AUDIT.md`, section 13: full tests/lint/build and browser suites pass; 36 Lighthouse samples were collected. Open boundaries are production 500 diagnosis, mobile performance targets, real Vercel/Nginx verification, old-worker upgrades and search-engine indexing. No publication or dependency change.
